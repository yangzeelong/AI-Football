# Roboflow 方案对比与下一步任务

工作目录：`C:\Proj\AI-Football-DEV`

目标：
- 对比当前项目与 Roboflow 风格方案的差异
- 复用 Roboflow 在检测、跟踪、数据闭环上的思路
- 保留 `hrnet-w48-dark` 作为 landmark 主干
- 让单视角输出更适合足球分析和后续任务 2

## 已确认的现状

- 当前项目已具备 RF-DETR 检测、人轨迹、球轨迹、26 点骨架、JSONL 输出和回放评估。
- 人体跟踪主要依赖 ByteTrack。
- 足球跟踪是轻量自定义 tracker，支持短时预测，但仍偏简单。
- 26 点 landmark 已接入 `hrnet-w48-dark`，这个方向保留。

## 需要做的事情

### P0：把 Roboflow 的可用思路落到当前工程

- 梳理 Roboflow 方案里真正有价值的部分：数据版本管理、主动学习、难例回收、工作流编排。
- 对比当前 detector 与 Roboflow 风格 detector 的差异，明确是否需要切换到更足球专用的检测器。
- 明确 Roboflow 方案里能直接借用的 tracker 思路，重点看球员追踪和球追踪的分离设计。

### P0：加强足球检测与跟踪

- 针对球被脚部/身体遮挡、小目标、远距离、反光点这几类难例做专项对比。
- 评估是否需要球专用 detector，而不是只依赖通用 person / ball 检测。
- 给球轨迹补更强的状态管理：观测、预测、丢失、恢复。
- 增加球与脚部关键点的邻近关系约束，减少误检和错跟踪。

### P1：加强人体跟踪稳定性

- 对多人交叉、短时遮挡、出画恢复场景做 ID 连续性检查。
- 评估是否需要更强的 tracker 参数或 appearance 约束。
- 统计短轨迹、ID switch、track fragment，作为调参依据。

### P1：加强 landmark 可用性

- 保留 `hrnet-w48-dark`，不要轻易替换主 landmark 主干。
- 对脚踝、脚跟、脚趾、手腕这些抖动大的点做更稳的时序处理。
- 把原始点和稳定化点分开输出，避免业务侧误用。
- 补齐低置信、缺失、预测点的状态标记。

### P1：补齐质量评估闭环

- 增加静止、快速运动、遮挡三类场景的分项统计。
- 增加球连续缺失区间、人体短轨迹区间、关键点抖动统计。
- 导出典型失败帧，作为下一轮训练或调参样本。

### P2：整理成可复用交付物

- 冻结 2D observation schema。
- 冻结 26 点名称、顺序、状态定义。
- 补一份 Roboflow 风格方案和当前项目方案的对比说明。
- 补一份可执行的运行说明，避免后续切环境时口径漂移。

## 建议顺序

1. 先做 detector / tracker 对比，确认球和人体的主要短板。
2. 再做球跟踪专项，优先解决漏检和遮挡。
3. 然后收紧人体跟踪和 landmark 稳定性。
4. 最后冻结 schema 和评估脚本。
